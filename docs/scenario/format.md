# Формат сценария

Файл экспорта: `*.atlas-scenario.json`, поле `format: "atlas-scenario"`, `formatVersion: 1`. Проверка и миграция — `src/scenario/schema.ts`.

## Что хранится

| Поле | Содержание | Происхождение |
|---|---|---|
| `engineVersion`, `historyBuildId`, `catalogVersion` | версии игрового движка, сборки исторических данных и каталога | система |
| `branch` | имя ветки, родитель и момент эпизода, от которого она продолжена | пользователь |
| `world` | `historical`: дата ветвления, правило продолжения истории (`stop` / `compatible`), изменения мира; или `test-scene` | пользователь / допущение |
| `region`, `frame` | область карты; начало плоской системы координат (фиксируется при первом объекте) | пользователь |
| `episode` | дата, время начала UTC, продолжительность, условия завершения | пользователь |
| `participants`, `relations`, `permissionRequired` | стороны и игровые отношения | допущение сценария |
| `objects` | начальное состояние: класс, сторона, положение, маршрут, задача, нагрузка, запас, историческая подпись | пользователь |
| `settings` | основные и расширенные настройки | пользователь |
| `weather` | источник, снимок данных, ручные условия, игровой пресет | данные источника / допущение |
| `seed` | зерно генератора | пользователь |
| `commands` | команды с временными отметками эпизода | пользователь |
| `changeLog` | журнал изменений с происхождением (`user` / `assumption`) | система |

Исторические факты в файл не копируются: при открытии ветка пересчитывается из исторической базы по `historyBuildId`, дате ветвления и изменениям. Поэтому исторические данные и пользовательские изменения имеют разное происхождение и не смешиваются.

## Проверка при загрузке

- Не JSON, чужой формат, отсутствующие обязательные поля, неизвестный игровой класс, сторона вне участников, повтор идентификаторов, повреждённый снимок погоды — понятная ошибка, файл не открывается.
- Более новая версия формата — ошибка «обновите атлас».
- Другая версия движка или каталога — предупреждение: журнал повтора может отличаться.
- Недостающие настройки дополняются значениями по умолчанию с предупреждением.

## Миграции

| Из | В | Что происходит |
|---|---|---|
| `legacy-sim` — сценарий прежней «Учебной симуляции» (поля `posts`, `objects`, `maxTicks`, без `format`) | 1 | Испытательная сцена. Посты → зенитные посты класса З-θ с прежним запасом (радиусы и вероятности — игрового класса). Профиль «Дуга» → пусковая с баллистической нагрузкой, «Бриз» → пусковая с крылатой нагрузкой, «Борт» → транспортный самолёт с перелётом. 1 прежний такт = 5 с; 1 у.е. = 1 км. Миграция записывается в журнал изменений как допущение. |

Старая ссылка `#/simulation` открывает редактор с перенесённым сценарием «Этапы по порядку».

## Хранение в браузере

- `atlas.scenario.autosave` — автосохранение текущего сценария (через 0,7 с после изменения); при открытии раздела предлагается восстановить.
- `atlas.scenario.slots` — список сохранённых (до 30). При переходе к другому сценарию текущий с несохранёнными изменениями сохраняется в список автоматически, поэтому подтверждение нужно только для удаления из списка.
- `atlas.weather.snapshots` — последние 12 погодных снимков для работы без сети.

Если хранилище браузера недоступно (приватный режим), работает только экспорт в файл.
